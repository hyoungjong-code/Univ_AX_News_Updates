# AI 기업-대학 계약 유형 분류 틀

AI 기업과 대학의 계약은 겉으로는 모두 "파트너십"이라고 발표되지만, 대학이 실제로 얻는 것과 부담하는 것이 크게 다르다. 아래 틀로 사례를 분류하고, 실제 수집된 사례가 맞지 않으면 유형을 합치거나 새로 만든다. 유형 이름보다 **비교 축**을 일관되게 채우는 것이 중요하다.

## 출발점이 되는 유형

| 유형 | 전형적 형태 | 예시 패턴 |
|---|---|---|
| A. 유료 전교 엔터프라이즈 라이선스 | 대학이 비용을 내고 전 구성원에게 교육용 엔터프라이즈 제품 제공 | ChatGPT Edu, Claude for Education 전교 도입 |
| B. 시스템·국가 단위 계약 | 대학 연합·주립대 시스템·정부가 일괄 계약 | 주립대 시스템 전체, 국가 교육부와의 협약 |
| C. 기존 플랫폼 번들(무료·저가) | 이미 쓰는 업무 도구(Workspace, M365)에 AI 기능을 포함 | Gemini for Education, Copilot 교육용 |
| D. 개인·학생 대상 프로모션 | 학교 계약 없이 학생 개인에게 무료·할인 제공 | 학생 1년 무료 요금제, 통신사 결합 |
| E. 연구·인프라 파트너십 | GPU·클라우드 크레딧, 공동 연구, 연구소 설립 | 연구용 컴퓨팅 지원, 공동 AI 연구센터 |
| F. 교육·인재양성 연계형 | 커리큘럼 공동 개발, 교수 연수, 인턴십을 라이선스와 묶음 | AI 리터러시 과정 공동 운영 |
| G. 멀티벤더·자체 플랫폼 | 여러 모델을 대학 자체 포털로 묶어 제공 | 대학 자체 AI 허브, API 기반 통합 플랫폼 |

한 사례가 여러 유형에 걸치면 주 유형 하나를 표기하고 보조 유형을 괄호로 단다 (예: "A (+F)").

## 비교 축 (유형별 비교표의 열)

- **계약 단위**: 단과대 / 대학 / 대학 시스템 / 국가
- **대상**: 교직원, 학생, 연구자 중 누구에게 제공하는지, 단계적 개방 여부
- **서비스 범위**: 채팅 도우미만 / 상위 모델·사용량 / 에이전트·코딩 도구 / API·자체 연동 / 학습 관리 시스템(LMS) 연동
- **비용 구조**: 대학 부담 / 무료 번들 / 학생 개인 부담 / 학과별 추가 과금, 공개된 금액·기간
- **데이터 조건**: 학습 데이터로 쓰지 않음 명시 여부, 보관 기간, 개인정보·FERPA·국내법 대응
- **교육·연구 연계**: 연수, 커리큘럼, 연구 지원 포함 여부
- **지속성 신호**: 파일럿 / 갱신 / 중단·전환 사례

## 유형별로 정리할 것

각 유형마다 다음을 1~2줄씩 쓴다:
- 특징 (무엇을 얻고 무엇을 부담하나)
- 장점과 위험 (비용 고착, 벤더 종속, 실사용률, 데이터 통제)
- 어떤 대학에 맞나 (예: 연구중심 대규모 대학, 재정 여력이 적은 지역대학)

기업 발표에 나온 "최대 규모", "학습효과 향상" 같은 주장은 유형 분석의 근거로 쓰지 말고, 계약 조건처럼 확인 가능한 사실로 분류한다.
